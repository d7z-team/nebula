# Mesh 协议与运行机制

每个 `Node` 拥有独立的套接字、信任根、成员视图和会话。宿主提供拓扑、业务路由与证书授权策略，节点提供加密传输、端点发现、逐跳中转和原生事件。[接入指南](quickstart.md)

## TLS 与成员身份

QUIC、直连 TCP 和中转内层使用同一协议标识 `nebula-mesh`。双方执行 TLS 1.3 双向证书认证，Go 核验签名、PKIX 链、EKU 和服务端名称。临时密钥交换使用 X25519MLKEM768。它为会话密钥提供混合密钥交换和前向保密。身份认证的抗量子强度另取决于部署使用的叶密钥、签发链及 TLS 支持的签名算法。节点禁用会话票据，每次新连接都交换实际的证书链。[TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446) · [TLS 配置](../identity.go)

每个成员有一个原生 IPv4 和一个原生 IPv6，同一网络中每个地址分别唯一。节点从证书的两个 IP SAN 取出地址，按网络序拼接 4 个 IPv4 字节和 16 个 IPv6 字节，得到 20 字节的 `PeerID`。邻接、签名消息和日志使用 `10.80.0.7@fd42::7` 这样的文本表示。网络名和允许路由的下游 CIDR 来自签名证书扩展。[证书配置](pki.md#证书配置)

拨号方用任一虚拟地址在拓扑中查找完整地址对。Go TLS 以该对中的 IPv4 字面量校验服务端 IP SAN，mesh 再校验网络、完整地址对、用途和委派范围。外层只需一个可达地址族即可承载内层双栈流量。

## 证书生命周期与宿主授权

`New` 克隆显式提供的 `*x509.CertPool`。替换信任锚时，宿主关闭节点，使用新根重建实例。`LocalCertificates.Client` 提供客户端凭据，`Server` 可覆盖服务端凭据。缺省的对象签名凭据复用客户端凭据；硬件签名器限制签名用途时，配置独立的 `Object`。证书按叶证书、中间 CA 的顺序提供。共用证书时，节点持有一份解析后的链，仍按各用途分别检查 EKU 与宿主授权。TLS 分别检查 clientAuth 和 serverAuth，对象签名检查 codeSigning。

`ReloadCertificates(ctx, set)` 先检查整组证书的私钥匹配、成员绑定、用途、路径与宿主许可，再原子替换。失败时调用方可以修正材料后重试。新握手在选择本机证书时读取当前凭据。已选择证书的握手继续使用所选证书；已建立的会话以握手实际出示的本机和对端证书为准。节点保留用于复查的公共证书。旧证书到期或被撤销后，相关路径失效，下次连接使用新凭据。[会话注册](../session.go) · [并发热加载测试](../authentication_test.go)

宿主通过 `Options.CheckChain` 对每条已通过 PKIX 验证的候选链作附加授权。钩子收到成员、方向（本机或对端）、用途和只读证书链。返回零时间及 nil 表示接受到证书链自身的期限；返回更早的截止时间可限制缓存授权；返回错误会否决该路径。只要存在一条获准的链，节点即可使用它。钩子在节点锁外执行，可以查询节点状态。同一张证书可能在握手、会话注册和授权复查时多次触发钩子，多个连接也可能并发调用它。实现应支持并发读取宿主策略，并响应 context 取消。数据包路径使用已验证的期限。

吊销信息、配置签发、修订顺序和持久化由宿主管理。宿主更新授权数据后调用 `Revalidate(ctx)`，或在到达自定义授权期限前调用它续验。节点重新审核本机凭据、活动会话和缓存事件，清理失权队列和中转电路，丢弃旧端点发现缓存。原生事件已经交付到宿主的数据由宿主处理。[授权更新](../topology_update.go) · [集成测试](../policy_integration_test.go)

改变任一虚拟地址会产生新的成员身份。将完整地址对交给另一台机器前，先使旧凭据过期或通过宿主钩子拒绝，执行 `Revalidate` 并清理旧队列。续证和换钥可以沿用原地址对。

## 启动与拓扑更新

宿主可以提供全网拓扑，也可以仅提供本机和已知邻居的最小视图，通过成员的 `Links` 和 `Endpoints` 发起认证连接。宿主可用 `Topology.Validate()` 预检拓扑。取得并验证新的成员资料后调用 `ApplyTopology(ctx, topology)`。每次调用安装一份独立副本，检查唯一地址与身份、网段、双向邻接、路由前缀和事件主题。格式错误保留当前视图；有效视图可以撤回本机成员资格。每一跳按自己的视图验证路径和邻接权限。[拓扑模型](../topology.go)

## 传输、帧格式与 MTU

| 路径 | IP 数据 | 控制与建链 |
| --- | --- | --- |
| QUIC v1 / UDP | 一个 QUIC DATAGRAM 承载一个完整 IP 包。发送时包长超过当前上限，会改用独立的可靠流发送整包。 | 使用 QUIC 双向流。握手分段、确认和丢包恢复由 QUIC 负责，底层套接字支持时启用路径 MTU 发现。 |
| TLS 1.3 / TCP | 专用 yamux 流承载带长度前缀的 IP 包。 | 各项操作使用独立的 yamux 流，同一 TCP 连接上的丢包可能延迟所有流。 |
| 多跳中继 | IP 流运行在两端新建的 TLS/yamux 会话中。 | 每一跳在已认证的 QUIC 或 TLS/TCP 邻接上打开流，两端再做一次双向 TLS 握手。 |

宿主按物理地址族提供 `UDP4`、`UDP6`、`TCP4`、`TCP6`。QUIC 握手与打洞共享该地址族的 UDP 套接字，UDP 与 TCP 可绑定相同端口号。QUIC 握手的初始包为 1200 字节，DATAGRAM 的可用载荷随路径变化。可靠流与数据报之间可能乱序。

双向流以一个字节标识操作。探活（1）、邻居通告（2）、事件推送（3）、端点查询（6）和事件获取（7）的请求与响应均带四字节大端长度前缀。通告正文使用 JSON；事件推送的请求体与事件获取的响应体使用 CMS DER。获取请求体为 64 字节小写十六进制事件 ID，推送成功返回空帧。

电路（4）以带长度前缀的路径请求开始，收到单字节成功应答后成为双向字节流。IP 流（5）逐包加长度前缀，同一发送方向复用已打开的流。每会话最多并发处理 64 个入站流，控制请求正文上限为 64 KiB。[收发实现](../session.go) · [电路建立](../circuit.go) · [QUIC DATAGRAM](https://www.rfc-editor.org/rfc/rfc9221)

应用可用 `RecommendedMTU(peer, ipv6, limit)` 设置到该对端的路由 MTU，并在切路后更新。支持 IPv6 的接口至少为 1280 字节，可借助可靠流通过载荷更小的路径。两端各自通过 `MaxIPSize` 约束完整内层包的大小。[IPv6 MTU 要求](https://www.rfc-editor.org/rfc/rfc8200#section-5)

## 发现、选路与中继

节点可以签发短期有效的端点介绍记录。QUIC 对端还可以报告它观察到的源 UDP 地址。查询经邻居送达目标，携带发起方的签名介绍，并带回目标的签名介绍。双方从实际 QUIC 套接字向候选端点发短包。端口受限 NAT 可能丢弃首次拨号。会合让双方先向对方的 UDP 端点发包，发起方随后在同一次连接尝试中重拨，每个已尝试的 UDP 端点最多重试一次。认证握手成功才确认直连可用。查询使用随机 ID 去重、已访问路径、转发扇出和跳数限制。若 NAT 随目的地改变外部端口，邻居观察到的地址可能无法用于直连。[发现与打洞](../discovery.go) · [候选端点拨号](../paths.go)

端点介绍有效期为一分钟。节点在端点、签名凭据或拓扑视图变更时重新签名，也在到期前十秒内刷新。邻居在通告中确认已接收记录的到期时间。确认值与本机缓存匹配时，后续通告可将帧空间留给事件清单。[发现通告](../discovery.go)

配置标记为 `restricted` 的成员只与拓扑中列出的邻居直连。需要让子网节点只连网关时，在两端声明双向邻接，把网关设为 `transit`，并提供宿主认可的物理端点。本地 `SetPeerPathPolicy` 还能为单一对端选择 `Auto`、`DirectOnly`、`RelayOnly` 或 `Blocked`。这些限制适用于拨号、打洞、会话准入及 QUIC 路径变化后的物理 UDP 收发。认证之前，UDP 过滤器只能识别物理端点。TCP 接入先检查源 IP，再用双向 TLS 区分共享地址的成员。TCP 确认及连接拆除由操作系统处理。[路径授权](../path_policy.go)

多个 `ConnectPeer(ctx, peer)` 调用共享同一对端的建链尝试。取消调用方的 context 会结束该次等待，节点仍负责完成建链，关闭节点会取消建链。直连优先尝试 UDP，随后尝试 TCP。对端重新发起并通过认证的同地址族同类型直连会替换该方向的旧会话，使 NAT 重建或路径封锁期间遗留的连接及时退出。周期性认证探测记录延迟、抖动和连续失败数，QUIC 还提供路径 RTT 与丢包数据。若当前路径代价仍在最低代价的 1.2 倍以内，节点继续使用当前路径。金丝雀探测受并发预算和时间间隔限制，用来建立备用路径。连续三次探测失败会关闭会话。内层协议可通过自身的丢包恢复在切路后继续传输。[选路与健康检查](../paths.go)

电路沿本地拓扑中的双向邻接建立，每个中间节点都须具有中继权限。各跳检查完整路径、环路、本机位置和认证过的相邻节点。寻路考虑最短路径和可绕过故障边的备选路径，每条电路最多经过 16 个节点，端点和中继都执行本机并发配额。中继可见路径、时间和密文字节数，内层 IP 数据由端点解密。撤销拓扑授权会关闭受影响的流。[电路实现](../circuit.go)

## 数据交付、整形与事件

原始 IP 端口校验源和目的地址是否分别由发送成员和接收成员持有。虚拟网段内优先检查地址的唯一归属，下游地址必须同时属于当前拓扑启用的前缀和这次端到端会话实际出示的证书所批准的前缀。发送队列绑定完整地址对，收包和出队时均核验源、目的地址。gVisor 网卡把路由表选定的网关交给 IP 端口，IP 转发由 gVisor 完成。[IP 端口](../ip_port.go) · [gVisor 网卡](../nebulagvisor/endpoint.go)

每个对端最多排队 64 个待发包，每个节点最多 512 个。`IPPort.ClearPending(addr)` 接受对端任一虚拟地址，丢弃该成员的积压包，并取消当前包的建链或整形等待。返回值只统计仍在队列里等待的包。随后写入该成员的新包可以立即排队。

节点级令牌桶允许 64 KiB 突发，计入本机发出的 IP 包、中继字节和事件传输。中继流按块整形，短探活和发现消息可以在数据等待时继续交换。计量单位是提交的应用字节，物理带宽还包括协议头和重传。

### 签名事件

拓扑成员的 `Topics` 授予对指定 `app/` 主题及其子树的发布权，`Subscribe` 按完整主题名匹配。节点验证原发布者、对象签名、主题和有效期，按事件 ID 去重后向直连邻居推送。邻居交换缓存清单以补发遗漏的事件。每个事件的载荷上限为 4 KiB，有效期为五分钟，每节点最多缓存 512 条。[事件实现](../events.go) · [签名对象](pki.md#签名对象)

`Publish` 返回的 ID 表示本机已接纳事件。远端交付依赖有效期内的邻接和缓存。宿主变更授权后可用 `Revalidate` 复查缓存，推送和补发也会在整形等待结束时复查事件及路径。`Subscription.Missed()` 统计本机因订阅缓冲区已满而丢弃的事件数。

## 运行状态

| 调用 | 用途 |
| --- | --- |
| `ControlStatus()` | 用 `Started` 判断收发是否启动，`Ready` 判断本机成员和凭据是否有效。还可查当前客户端证书序列号、已用电路、拨号失败次数和最近一次建链错误。 |
| `Peers()` | 查看每条已建立路径的传输、是否活动、握手证书与授权截止时间，以及 RTT、抖动、探测失败数、QUIC 计数和流回退次数。 |
| `IPPort.Stats()` | 查看当前排队数、已收发和已拒绝的包数，以及最近一次记录的丢包原因。 |

状态查询和建议 MTU 均可在运行中读取。关闭节点会取消后台任务、等待任务退出，并释放交给该节点的监听器和套接字。[状态 API](../status.go) · [接入示例](quickstart.md)
