# Mesh 协议与运行机制

每个 `Node` 持有自己的传输入口、信任根、成员视图和会话。入口可以是独占的物理套接字，也可以是与网站共享端口时分配给节点的逻辑分支。宿主提供拓扑、业务路由与证书授权策略，节点提供加密传输、端点发现、逐跳中转和原生主题消息。[接入指南](integration.md) · [端口复用](portshare.md)

## TLS 与成员身份

QUIC、直连 TCP 和中转内层使用同一协议标识 `nebula-mesh`。双方执行 TLS 1.3 双向证书认证，Go 的 TLS 和 X.509 实现核验握手签名、PKIX 链与 EKU。临时密钥交换使用 X25519MLKEM768。它为会话密钥提供混合密钥交换和前向保密。身份认证的抗量子强度另取决于部署使用的叶密钥、签发链及 TLS 支持的签名算法。节点禁用会话票据，每次新连接都交换实际的证书链。[TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446) · [TLS 配置](../identity.go)

每个成员有一个原生 IPv4 和一个原生 IPv6，同一网络中每个地址分别唯一。节点从证书的两个 IP SAN 取出地址，按网络序拼接 4 个 IPv4 字节和 16 个 IPv6 字节，得到 20 字节的 `PeerID`。邻接、签名消息和日志使用 `10.80.0.7@fd42::7` 这样的文本表示。网络名和允许路由的下游 CIDR 来自签名证书扩展。[证书配置](pki.md#证书配置)

按主地址拨号时，节点从静态配置、有效签名介绍或认证会话中取得完整地址对。`ConnectPeerID` 直接采用调用方选定的地址对。Go TLS 以该对中的 IPv4 字面量校验服务端 IP SAN，mesh 再校验网络、完整地址对、用途和委派范围。用 `ConnectEndpoint` 拨物理端点时，节点从对端证书取得地址对，按本机显式信任根构建 PKIX 链，并检查固定集群 CA、serverAuth 和宿主钩子。外层只需一个可达地址族即可承载内层双栈流量。

## 证书生命周期与宿主授权

`New` 克隆显式提供的 `*x509.CertPool` 并固定 `Options.ClusterCA` 的证书。替换信任锚时，宿主关闭节点，使用新根重建实例。`LocalCertificates.Client` 提供客户端凭据，`Server` 可覆盖服务端凭据。缺省的对象签名凭据复用客户端凭据；硬件签名器限制签名用途时，配置独立的 `Object`。证书按叶证书、中间 CA 的顺序提供。共用证书时，节点持有一份解析后的链，仍按各用途分别检查 EKU 与宿主授权。TLS 分别检查 clientAuth 和 serverAuth，对象签名检查 codeSigning。

`ReloadCertificates(ctx, set)` 先检查整组证书的私钥匹配、成员绑定、用途、路径与宿主许可，再原子替换。失败时调用方可以修正材料后重试。新握手在选择本机证书时读取当前凭据。已选择证书的握手继续使用所选证书；已建立的会话以握手实际出示的本机和对端证书为准。节点保留用于复查的公共证书。旧证书到期或被撤销后，相关路径失效，下次连接使用新凭据。[会话注册](../session.go) · [并发热加载测试](../authentication_test.go)

宿主通过 `Options.CheckChain` 对每条已通过 PKIX 验证的候选链作附加授权。钩子收到成员、方向（本机或对端）、用途和只读证书链。通过 `ChainCheck.Usage == x509.ExtKeyUsageCodeSigning` 识别对象签名用途。返回零时间及 nil 表示接受到证书链自身的期限；返回更早的截止时间可限制缓存授权；返回错误会否决该路径。只要存在一条获准的链，节点即可使用它。钩子在节点锁外执行，可以查询节点状态。同一张证书可能在握手、会话注册和授权复查时多次触发钩子，多个连接也可能并发调用它。实现应支持并发读取宿主策略，并响应 context 取消。数据包路径使用已验证的期限。

吊销信息、配置签发、修订顺序和持久化由宿主管理。宿主更新授权数据后调用 `Revalidate(ctx)`，或在到达自定义授权期限前调用它续验。节点重新审核本机凭据、活动会话和缓存主题消息，清理失权队列和中转电路，丢弃旧端点发现缓存。宿主处理已经交付的主题消息。[授权更新](../topology_update.go) · [集成测试](../policy_integration_test.go)

改变任一虚拟地址会产生新的成员身份。将完整地址对交给另一台机器前，先使旧凭据过期或通过宿主钩子拒绝，执行 `Revalidate` 并清理旧队列。续证和换钥可以沿用原地址对。

## 启动与拓扑更新

宿主可以只提供本机成员信息，在 `Start` 后调用 `ConnectEndpoint` 接入任一可达成员。静态成员条目声明主地址绑定、邻接和本地业务授权。移除远端静态条目会撤回其静态授权；有效集群成员仍能以认证的主地址通信。即时封锁对端使用 `Blocked`，撤回证书通过 `CheckChain` 和 `Revalidate` 生效。宿主可用 `Topology.Validate(cluster)` 对照 CA 地址规划预检拓扑。本机签名介绍的尺寸还取决于对象签名证书链，由节点在安装配置时检查。取得并验证新的成员资料后调用 `ApplyTopology(ctx, topology)`。每次调用安装一份独立副本，检查唯一地址与身份、网段、双向邻接、路由前缀和发布主题。格式错误保留当前视图；有效视图可以撤回本机成员资格。每一跳按自己的视图验证路径和邻接权限。[拓扑模型](../topology.go)

## 传输、帧格式与 MTU

| 路径 | IP 数据 | 控制与建链 |
| --- | --- | --- |
| QUIC v1 / UDP | 一个 QUIC DATAGRAM 承载一个完整 IP 包。整包超过路径的数据报预算、仍在对端收包上限内时，改用可靠流发送。 | 使用 QUIC 双向流。握手分段、确认和丢包恢复由 QUIC 负责，底层套接字支持时启用路径 MTU 发现。 |
| TLS 1.3 / TCP | 专用 yamux 流承载带长度前缀的 IP 包。 | 各项操作使用独立的 yamux 流，同一 TCP 连接上的丢包可能延迟所有流。 |
| 多跳中继 | IP 流运行在两端新建的 TLS/yamux 会话中。 | 每一跳在已认证的 QUIC 或 TLS/TCP 邻接上打开流，两端再做一次双向 TLS 握手。 |

宿主按物理地址族提供 `UDP4`、`UDP6`、`TCP4`、`TCP6`。QUIC 握手与打洞共享该地址族的 UDP 套接字，UDP 与 TCP 可绑定相同端口号。QUIC 握手的初始包为 1200 字节，DATAGRAM 的可用载荷随路径变化。可靠流与数据报之间可能乱序。

完成双向 TLS 认证后，拨号端先发送本机的完整 IP 收包上限，接受端读出后回送自己的上限。每个值是两字节大端无符号整数，范围为 1280 至 65535。QUIC 使用客户端发起的第一条双向流专门完成交换；TCP 和中继直接在 TLS 字节流上交换，然后启动 yamux。交换受建链超时限制，完成后会话才可承载业务。中间节点只转发内层 TLS 密文。

### 操作码和流边界

每条新业务流的首字节指定操作。表中 `F(x)` 表示四字节无符号大端长度和紧随其后的 `x`，长度只计算正文。普通控制请求正文上限为 65,536 字节，应答沿请求所在的流返回。接收方按长度读满一帧，TLS record 和底层分段可以在任意位置切分帧。

| 首字节 | 操作 | 请求方写入首字节后的内容 | 接收方返回及结束方式 |
| --- | --- | --- | --- |
| `01` | 探活 | `F(探测字节)`，0～32 字节 | 原样返回 `F(探测字节)` 后关流。 |
| `02` | 邻居通告 | `F(通告 JSON)` | 返回自己的 `F(通告 JSON)` 后关流。两个方向的正文均以 64 KiB 为限。 |
| `03` | 查询地址或会合 | `F(查询 JSON)` | 返回零到多帧 `F(签名介绍的原始 CMS DER)`，每个成员一帧，最多 64 个成员，关流结束此分支。 |
| `04` | 建立中继电路 | `F(路径 JSON)` | 成功后写入单字节 `01`，随后同一条流承载端到端 TLS。建电路失败时关流。 |
| `05` | 传送 IP | 连续写入 `F(完整 IP 包)`，每包受对端通告的收包上限约束 | 接收端逐帧交付，直到流结束。反向发送使用反向发起的 IP 流。 |
| `06` | 推送主题消息 | `F(CMS DER)`，完整 CMS 上限 44 KiB | 本机接纳或识别出已接纳的副本后返回空帧 `00 00 00 00` 并关流。 |
| `07` | 按 ID 获取主题消息 | `F(ID)`，正文为 64 字节小写十六进制 ASCII | 命中且授权有效时返回 `F(原始 CMS DER)` 后关流。获取方从签名内容计算 ID，与所请求的 ID 匹配后接纳。缺失或失权时直接关流。 |

例如 Ping 请求 `01 00 00 00 03 70 32 70` 的完整响应为 `00 00 00 03 70 32 70`。空帧也有四个长度字节，可与直接结束流区分。未知操作、无效请求或未获准的操作可直接结束本条流。调用方以该操作规定的响应判断成功。对于查询，某分支提前结束仍可能从缓存或其他邻居取得有效匹配。`ResolveIP` 返回本次取得的结果，按匹配前缀长度降序、再按成员身份排序。[接收分派](../session.go) · [查询处理](../lookup.go) · [固定字节用例](../wire_test.go)

### 控制消息的 JSON 格式

发送端使用下表的 lowerCamelCase 字段名。接收端使用 Go 标准库 `encoding/json` 解码，优先匹配完全同名的字段，也能匹配仅大小写不同的字段，并忽略未知字段。对象键的排列顺序可变。签名对象的接收者始终用收到的原始字节验证签名和计算标识，缓存及补发使用原始 CMS DER。

| 对象 | 字段与编码 |
| --- | --- |
| 邻居通告 | `observed` 为观察到的对端 UDP 地址和端口，空字符串表示无观测。`record` 为标准 Base64 编码的签名介绍，可为 `null`。`seen` 为已见介绍的 `expires` 的 Unix 纳秒时间戳，零值省略。`inventory` 是主题消息 ID 字符串数组，可为 `null`。 |
| 地址查询 | `id` 为 16 个随机字节的小写十六进制字符串。`ip` 为查询地址。`origin` 为发起方签名介绍的 Base64。`visited` 按经过的顺序列出成员，从发起方开始。`budget` 为传给下一跳的剩余时长，以正整数纳秒表示。仅指定成员会合时带上 `target`，此时 `ip` 为其 IPv4 主地址。 |
| 中继路径 | `path` 为按顺序排列的成员字符串数组，包含起点、中继和终点，共 3～16 项。 |
| 签名封装 | CMS 内部的业务正文为 UTF-8 JSON 对象，包含签名成员 `publisher` 及对象 `value`。介绍使用 CMS 用途字符串 `introduction`，主题消息使用 `publication`。两个用途分别验签。 |
| 介绍的 `value` | `endpoints` 是最多 16 个物理端点的数组，可为 `null`。每项形如 `{"network":"udp","address":"[2001:db8::1]:4242"}`，传输名取 `udp` 或 `tcp`。`routedPrefixes` 为下游 CIDR 字符串数组，空时省略。`expires` 为到期时间。 |
| 主题消息的 `value` | `origin` 为原发布者，须与 `publisher` 和签名证书身份一致。`topic` 为完整应用主题。`nonce` 由发布者生成，是 16 个随机字节的小写十六进制字符串。`payload` 采用标准 Base64，解码后最多 4 KiB，空载荷可为 `""` 或 `null`。`expires` 为到期时间。消息 ID 取 `value` 原始 JSON 字节的 SHA-256，以 64 个小写十六进制字符表示。 |

上述成员身份均使用 `IPv4@IPv6` 字符串，例如 `10.13.0.1@fd13::1`。到期时间使用 RFC 3339 字符串，支持纳秒精度。`seen` 和 `budget` 均按有符号 64 位整数解码。`seen` 按纳秒精确比较，使用 IEEE 754 双精度浮点值中转会丢失有效位。[签名封装](../identity.go) · [主题消息](../publication.go) · [CMS 格式](pki.md#签名对象)

### 路由 MTU

应用可用 `RecommendedMTU(peer, ipv6, limit)` 设置到该对端的路由 MTU，并在切路后更新。支持 IPv6 的接口至少为 1280 字节，可借助可靠流通过载荷更小的路径。已建路径取本机上限、路径的 `RemoteIPLimit` 和调用方上限的最小值，QUIC 再按数据报预算和 IPv6 最低 MTU 调整。超过对端上限的排队包通过 `ObserveTransmit` 返回 `ErrPacketTooLarge`，后续小包继续发送。[IPv6 MTU 要求](https://www.rfc-editor.org/rfc/rfc8200#section-5)

## 发现、选路与中继

地址查询经过现有的认证邻接。查询集群主地址时，节点按 IPv4 或 IPv6 所有者查找有效的签名介绍。查询下游地址时，各网关分别以其最具体的已授权前缀应答，邻居也可转交缓存的签名原文。每跳最多同时查询四个邻居，依次处理剩余分支并传递剩余时间预算。每条回答独立分帧，一次转发最多返回 64 个成员。查询 ID、已访问路径和跳数限制重复转发。[地址查询](../lookup.go)

介绍中的下游前缀取本机拓扑与对象签名证书委派的交集。端点按显式通告、本机拓扑、监听地址、有效 NAT 观测的顺序去重，最多取 16 个。固定端点和授权前缀优先占用签名记录空间，再按物理地址和端口顺序纳入装得下的观测。记录有效期为一分钟，在到期前十秒内刷新。端点、签名凭据或拓扑视图变化也会触发重新签名。接收方独立验签，缓存寿命受记录、证书和宿主授权中最早的截止时间约束。邻居通过通告确认收到记录的原始到期时间，后续通告可以省去已确认的记录。[签名介绍](../introduction.go) · [邻居通告](../discovery.go)

NAT 会合请求须到达目标本人。双方交换签名介绍后，各自从静态配置和有效介绍中依次取出候选端点，按传输协议和物理地址去重。每轮打洞使用 QUIC 的 UDP 套接字，向每个获准且地址族可用的 UDP 端点各发一包。节点为每个 QUIC 邻居按地址族各保留一条有效的 UDP 源端点观测，新观测须通过物理端点校验才会替换旧值。若 NAT 按目的地分配映射，能否直连仍取决于实际握手。[会合与打洞](../discovery.go) · [候选端点拨号](../dial.go)

配置标记为 `restricted` 的成员只与拓扑中列出的邻居直连。需要让子网节点只连网关时，在两端声明双向邻接，把网关设为 `transit`，并提供宿主认可的物理端点。本地 `SetPeerPathPolicy` 还能为单一对端选择 `Auto`、`DirectOnly`、`RelayOnly` 或 `Blocked`。这些限制适用于拨号、打洞、会话准入及 QUIC 路径变化后的物理 UDP 收发。认证之前，UDP 过滤器只能识别物理端点。TCP 接入先检查源 IP，再用双向 TLS 区分共享地址的成员。TCP 确认及连接拆除由操作系统处理。[路径授权](../path_policy.go)

本机启用 `Options.HideEndpoints` 时，同一份签名介绍中的 `endpoints` 为空，邻居通告、查询来源、实时应答和缓存应答均遵守这一选择。QUIC 邻居仍可向本机报告它看到的源地址。本机跳过该观测，收到会合查询时仅回复签名介绍。主动连接和已建邻接仍能双向传输。电路检查的是逐跳身份与转发授权，允许没有公布端点的成员担任中继。[配置隐藏节点](integration.md#让节点通过已连接的邻居提供中继)

按成员建链时，任一方向注册的获准会话都能唤醒等待者。若一次建链成功但路径在等待结束前已被撤回，节点按当前策略再试一次。直连失败时也会重新读取策略，因此拨号期间从 `DirectOnly` 切到 `Auto` 可在同一轮尝试中继，切到 `Blocked` 则返回 `ErrPathPolicy`。[拨号实现](../dial.go) · [配置常驻邻居](integration.md#跨机器连接)

按成员身份直连时优先拨 UDP。两种传输都有候选时，TCP 等待 250 毫秒或 `DialTimeout` 的一半，取较短者。UDP 候选提前耗尽会立即启动 TCP。每种传输按顺序拨各自的端点，一条共享建链尝试最多并行一路 UDP 和一路 TCP。首条完成认证和注册的可用路径会结束这轮竞拨。QUIC 使用迁移后的当前地址，入站 TCP 的临时源端口只标识当前连接。每个成员在同方向、同传输和同地址族最多保留两条有效直连。

常驻邻居按顺序轮转，共有 4 个专用的后台建链名额。主题推送、补取和备用线路探测共用另外 8 个名额，因此发布任务等待带宽时，新邻居仍能接入。已建会话另有独立探活名额。认证探测记录延迟、抖动和连续失败数，QUIC 还提供路径 RTT 与丢包数据。金丝雀定期尝试建立备线。UDP 试拨失败且会合成功时，本轮优先试拨新获知的可用 UDP 端点。地址未变且原端点仍有效时，双方打洞后重试原端点。每轮最多重试一次。连续三次健康探测失败会关闭相应会话。[选路与健康检查](../paths.go)

发送 IP 包时，若上次一般流量使用的路径仍获授权，且代价在最低值的 1.2 倍以内，就继续使用它。VIP 或下游地址需要另一张会话证书的授权时，只为该包选择合格路径。`Paths()` 和 `RecommendedMTU` 反映当前评分；查看状态、确认已有连接或后台探活都保留业务发送记录。[出队与发送](../ip_transmit.go)

一条电路最多包含 16 个节点，每跳检查整条路径、双向邻接、已认证的相邻成员及中间节点的 `Transit` 权限。中继先在一个 `DialTimeout` 内读完首帧，再按剩余路径长度给下游建链和上游就绪确认设置同一截止时间。中继可见路径、时间和密文字节数，只有两个端点能解密内层 IP 数据。撤销转发授权会关闭受影响的电路。

节点先从目标反向计算最短跳数，再从短到长枚举无环路径。一次建链在枚举阶段最多检查 4096 个邻接项、试拨八条电路。预算耗尽时，下次建链可在同一拓扑继续搜索。若接续搜索已到末尾且尚未找到候选，可用本轮剩余预算从头查找。[电路与搜索实现](../circuit.go)

## 数据交付、整形与主题消息

原始 IP 端口按完整成员身份排队。入队时检查当前拓扑，实际收发时按端到端会话的双端身份复核。主地址按唯一归属匹配，VIP 和下游路由分别取拓扑与会话证书精确地址、前缀授权的交集。广播与组播按目的地址的作用域、成员子网和接收方订阅决定交付范围。[广播与组播](addressing.md#广播与组播) · [出队和发送](../ip_transmit.go)

同一成员的主地址、VIP、下游地址和组投递共享一个有界队列。拓扑更新会清理失去授权的等待包，取消仍在等待建链或带宽的失权包。宿主也可调用 `IPPort.ClearPending(peerID)` 清理该成员的整个队列。[队列与地址授权](addressing.md)

节点级令牌桶允许 64 KiB 突发，计入本机发出的 IP 包、中继字节和主题消息传输。中继流按块整形，短探活和发现消息可以在数据等待时继续交换。计量单位是提交的应用字节，物理带宽还包括协议头和重传。

### 签名主题消息

拓扑成员的 `Topics` 授予对指定 `app/` 主题及其子树的发布权，`Subscribe` 按完整主题名匹配。节点验证原发布者、对象签名、主题和有效期，按消息 ID 去重。首次接纳后，节点在后台名额可用时向其余直连邻居各推送一次。错过推送的邻居可通过后续通告中的缓存清单补取签名原文。每条主题消息的载荷上限为 4 KiB，有效期为五分钟，每节点最多缓存 512 条。[主题消息实现](../publication.go) · [签名对象](pki.md#签名对象)

`Publish` 返回的 ID 表示本机已接纳主题消息。远端交付依赖有效期内的邻接和缓存。宿主变更授权后可用 `Revalidate` 复查缓存，推送和补发也会在整形等待结束时复查主题消息及路径。`Subscription.Missed()` 统计本机因订阅缓冲区已满而丢弃的主题消息数。

## 运行状态

`ControlStatus()` 报告本机资格、活动电路、拨号统计和 TCP、UDP 监听错误。`Paths()` 返回各会话的证书、授权期限和测量值。两种状态都是本机快照。排查某次业务交付时，将实际提交路径与应用回执关联。[状态 API](../status.go) · [运行状态与排障](integration.md#主题消息与运行状态)
