# Mesh 协议与运行机制

每个 `Node` 持有自己的传输入口、信任根、成员视图和会话。入口可以是独占的物理套接字，也可以是与网站共享端口时分配给节点的逻辑分支。宿主提供拓扑、业务路由与证书授权策略，节点提供加密传输、端点发现、逐跳中转和原生主题消息。[接入指南](integration.md) · [端口复用](portshare.md)

## TLS 与成员身份

QUIC、直连 TCP 和中继内层 TLS 使用节点创建时设置的 `TransportOptions.ALPN`。空值使用 `nebula-mesh`，自定义值为 1 至 255 字节，按字节精确匹配。该值出现在客户端的 ClientHello 中。更换标识时，两端节点和分流器须使用同一个新值。[TLS 配置](../handshake.go)

双方使用 TLS 1.3 双向认证，核验握手签名、PKIX 链及证书用途。密钥交换默认采用 Go 启用的组，可协商混合抗量子组或传统组。需要强制混合密钥交换的节点可限定允许的组。身份与授权的抗量子保障还取决于节点签名密钥及其签发链。节点禁用会话票据，每次新连接都重新认证双方的节点证书。[握手配置](integration.md#跨机器连接) · [TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446)

TLS 只传普通根直接签发的节点证书。节点以公钥指纹 `PeerID` 标识。主动建立 TLS 的对端可以取得节点公钥、证书、签发者及协议标识，同一公钥可跨会话关联。内部地址、网络名、VIP 和路由在独立的集群授权和签发链中。[证书配置](pki.md#证书配置)

TLS 认证后，双方先用绑定当前会话的标记核对集群 CA 指纹。拨号端只向本机拓扑、可信入口列表或有效签名介绍认可的公钥发送授权。响应端验证来方的授权链、TLS 公钥绑定及本机策略后，再回复自己的授权。因此入口可以接纳此前未知的成员，拨号端也会在注册会话前验证入口的成员资格。应用流和 IP 包在会话注册后交付。[授权交换](../handshake.go) · [会话注册](../session.go)

## 证书生命周期与宿主授权

每次握手固定本端实际出示的凭据。热加载后，新握手和新签名使用新凭据，已有会话仍按原证书复查。握手发送集群授权前，节点按当前策略核对接收方并登记写入。与策略提交并发时，尚在校验的握手按新策略重查，已经登记的写入沿用原握手期限。[授权交换](../handshake.go) · [策略提交](../topology_update.go)

已注册会话在控制请求开流后、邻居通告生成后及每条查询应答写出前复核接收方。各节点按公钥撤权并完成复查后，该身份无法再通过这些节点取得新生成的签名介绍、主题消息或 IP 载荷。[宿主撤权与生效范围](integration.md#选择本机安全策略)

## 运行实例与路径归属

每次 `New` 生成独立的 `InstanceID`。该节点的 TCP、QUIC、中继内层会话和签名介绍都使用它。换证、NAT 换址和切路保留同一标识。路径注册按成员串行裁决，同一 `PeerID` 的现有可用路径只接受来自同一实例的新路径。竞争实例的认证会话被拒绝，介绍单独记入本机诊断。仅有签名介绍时，记录中的时间和端点可用于发现；它们不能证明两个进程同时在线。

收到竞争握手时，节点记录原实例尚未关闭的认证路径所用的凭据和 TLS 用途。复核优先使用下一个可用的探活名额，向原实例发出新的认证 Ping。只有在确认期限内收到有效应答才确认冲突。已确认的约束在全部路径断线后仍然生效，原实例可以重新认证接入。普通重启在原路径失效且没有已确认冲突时可以直接建链。发送队列绑定已知目标实例，整形结束后再次核对，实例变更时丢弃旧包。[冲突诊断与恢复](integration.md#排查重复地址与实例)

## 启动与拓扑更新

每个节点按宿主提供的本地视图验证邻接、转发权限和主题发布权。宿主用 `Topology.Validate(cluster)` 预检配置，运行中用 `ApplyTopology(ctx, topology)` 安装完整视图。变更本机通告的端点或下游前缀时，节点还会检查签名介绍能否装入协议帧。[拓扑模型](../topology.go) · [策略更新的生效范围](integration.md#选择本机安全策略)

## 传输、帧格式与 MTU

| 路径 | IP 数据 | 控制与建链 |
| --- | --- | --- |
| QUIC v1 / UDP | 一个 QUIC DATAGRAM 承载一个完整 IP 包。整包超过路径的数据报预算、仍在对端收包上限内时，改用可靠流发送。 | 使用 QUIC 双向流。握手分段、确认和丢包恢复由 QUIC 负责，底层套接字支持时启用路径 MTU 发现。 |
| TLS 1.3 / TCP | 专用 yamux 流承载带长度前缀的 IP 包。 | 各项操作使用独立的 yamux 流，同一 TCP 连接上的丢包可能延迟所有流。 |
| 多跳中继 | IP 流运行在两端新建的 TLS/yamux 会话中。 | 每一跳在已认证的 QUIC 或 TLS/TCP 邻接上打开流，两端再做一次双向 TLS 握手。 |

宿主在 `Options.Transport` 中按物理地址族提供 `UDP4`、`UDP6`、`TCP4`、`TCP6`。QUIC 握手与打洞共享该地址族的 UDP 套接字，UDP 与 TCP 可绑定相同端口号。QUIC 握手的初始包大小设置为 1200 字节，DATAGRAM 的可用载荷随路径变化。可靠流与数据报之间可能乱序。

双向 TLS 完成后，QUIC 使用发起端的第一条双向流，TCP 和中继直接使用 TLS 字节流。双方以集群 CA 的完整 DER 的 SHA-256 为上下文，用标签 `EXPORTER-nebula-cluster` 导出 64 字节。发起端发送前 32 字节，响应端核对后回复后 32 字节。知道集群 CA 指纹的对端可以计算自己会话的导出值，拨号端仍须按前述入口策略决定是否披露授权。[TLS exporter](https://www.rfc-editor.org/rfc/rfc8446#section-7.5)

随后发起端发送一帧授权，响应端验证后回复相同结构。四字节大端正文长度后依次是两字节大端 IP 收包上限（1280～65535）、16 字节非零 `InstanceID` 和逐张拼接的 DER 授权链。接收方按 ASN.1 长度拆出各证书，授权链上限为 24 KiB。TCP 直连和中继电路均在授权交换完成后启动 yamux。[授权帧格式](../handshake.go) · [传输接入](../session.go)

### 操作码和流边界

每条新业务流的首字节指定操作。表中 `F(x)` 表示四字节无符号大端长度和紧随其后的 `x`，长度只计算正文。普通控制请求正文上限为 65,536 字节，应答沿请求所在的流返回。接收方按长度读满一帧，TLS record 和底层分段可以在任意位置切分帧。

| 首字节 | 操作 | 请求方写入首字节后的内容 | 接收方返回及结束方式 |
| --- | --- | --- | --- |
| `01` | 探活 | `F(探测字节)`，0～32 字节 | 原样返回 `F(探测字节)` 后关流。 |
| `02` | 邻居通告 | `F(通告 JSON)` | 返回自己的 `F(通告 JSON)` 后关流。两个方向的正文均以 64 KiB 为限。 |
| `03` | 查询地址或会合 | `F(查询 JSON)` | 返回零到多帧 `F(签名介绍的原始 CMS DER)`，每个成员一帧，最多 64 个成员，关流结束此分支。 |
| `04` | 建立中继电路 | `F(路径 JSON)` | 成功后写入单字节 `01`，随后同一条流承载端到端 TLS。建电路失败时关流。 |
| `05` | 传送 IP | 连续写入 `F(完整 IP 包)`，每包受对端通告的收包上限约束 | 接收端逐帧交付，直到流结束。反向发送使用反向发起的 IP 流。 |
| `06` | 推送主题消息 | `F(CMS DER)`，完整 CMS 上限 44 KiB | 本机接纳或识别出已接纳的副本后返回空帧 `00 00 00 00` 并关流。 |
| `07` | 按 ID 获取主题消息 | `F(ID)`，正文为 64 字节小写十六进制 ASCII | 命中且授权有效时返回 `F(原始 CMS DER)` 后关流。获取方从签名内容计算 ID，与所请求的 ID 匹配后接纳。缺失或失权时直接关流。 |

例如 Ping 请求 `01 00 00 00 03 70 32 70` 的完整响应为 `00 00 00 03 70 32 70`。空帧也有四个长度字节，可与直接结束流区分。未知操作、无效请求或未获准的操作可直接结束本条流。调用方以该操作规定的响应判断成功。查询分支提前结束时，其他邻居仍可提供有效应答。[接收分派](../session.go) · [查询处理](../lookup.go) · [固定字节用例](../wire_test.go)

### 控制消息的 JSON 格式

发送端使用下表的 lowerCamelCase 字段名。接收端使用 Go 标准库 `encoding/json` 解码，优先匹配完全同名的字段，也能匹配仅大小写不同的字段，并忽略未知字段。对象键的排列顺序可变。签名对象的接收者始终用收到的原始字节验证签名和计算标识，缓存及补发使用原始 CMS DER。

| 对象 | 字段与编码 |
| --- | --- |
| 邻居通告 | `observed` 为观察到的对端 UDP 地址和端口，空字符串表示无观测。`record` 为标准 Base64 编码的签名介绍，可为 `null`。`seen` 为已见介绍的 `expires` 的 Unix 纳秒时间戳，零值省略。`inventory` 是主题消息 ID 字符串数组，可为 `null`。 |
| 地址查询 | `id` 为 16 个随机字节的小写十六进制字符串。`ip` 为查询地址。`origin` 为发起方签名介绍的 Base64。`visited` 按经过的顺序列出成员，从发起方开始。`budget` 为传给下一跳的剩余时长，以正整数纳秒表示。仅指定成员会合时带上 `target`，此时 `ip` 为空字符串。 |
| 中继路径 | `path` 为按顺序排列的成员字符串数组，包含起点、中继和终点，共 3～16 项。 |
| 签名封装 | CMS 内部的业务正文为 UTF-8 JSON 对象，包含签名成员 `publisher` 及对象 `value`。介绍使用 CMS 用途字符串 `introduction`，主题消息使用 `publication`。两个用途分别验签。 |
| 介绍的 `value` | `ipv4`、`ipv6` 必须与已验证授权相同。`instance` 为 16 字节实例标识的小写十六进制字符串。`endpoints` 是最多 16 个物理端点的数组，可为 `null`。每项形如 `{"network":"udp","address":"[2001:db8::1]:4242"}`，传输名取 `udp` 或 `tcp`。`routedPrefixes` 为下游 CIDR 字符串数组，空时省略。`expires` 为到期时间。 |
| 主题消息的 `value` | `origin` 为原发布者，须与 `publisher` 和签名证书身份一致。`topic` 为完整应用主题。`nonce` 由发布者生成，是 16 个随机字节的小写十六进制字符串。`payload` 采用标准 Base64，解码后最多 4 KiB，空载荷可为 `""` 或 `null`。`expires` 为到期时间。消息 ID 取 `value` 原始 JSON 字节的 SHA-256，以 64 个小写十六进制字符表示。 |

上述成员身份均使用公钥指纹。到期时间使用 RFC 3339 字符串，支持纳秒精度。`seen` 和 `budget` 均按有符号 64 位整数解码。`seen` 按纳秒精确比较，使用 IEEE 754 双精度浮点值中转会丢失有效位。[签名封装](../identity.go) · [主题消息](../publication.go) · [CMS 格式](pki.md#签名对象)

### 路由 MTU

应用可用 `RecommendedMTU(peer, ipv6, limit)` 设置到该对端的路由 MTU，并在切路后更新。支持 IPv6 的接口至少为 1280 字节，可借助可靠流通过载荷更小的路径。已建路径取本机上限、路径的 `RemoteIPLimit` 和调用方上限的最小值，QUIC 再按数据报预算和 IPv6 最低 MTU 调整。超过对端上限的排队包通过 `ObserveTransmit` 返回 `ErrPacketTooLarge`，后续小包继续发送。接收端在可靠 IP 流的帧头检查本机 `MaxIPSize`。超限时直接结束该流，已有 IP 端口的 `RejectedInbound` 加一，同一会话仍可接收新的数据流。[IPv6 MTU 要求](https://www.rfc-editor.org/rfc/rfc8200#section-5)

## 发现、选路与中继

地址查询经过现有的认证邻接。查询集群主地址时，节点按 IPv4 或 IPv6 所有者查找有效的签名介绍。查询下游地址时，各网关分别以其最具体的已授权前缀应答，邻居也可转交缓存的签名原文。每跳最多同时查询四个邻居，依次处理剩余分支并传递剩余时间预算。每条回答独立分帧，一次转发最多返回 64 个成员。查询 ID、已访问路径和跳数限制重复转发。`ResolveIP` 在本机缓存未命中时发起查询，`RefreshIP` 对下游地址直接发起或加入同一查询。[地址查询](../lookup.go)

介绍中的下游前缀取本机拓扑与对象签名证书委派的交集。按显式通告、本机拓扑、监听地址、有效 NAT 观测的顺序收集端点。宿主的发布回调在去重和分配 16 个名额之前筛选候选。来源与观测者只用于本机决策。固定端点和授权前缀优先占用签名记录空间，再按物理地址和端口顺序纳入装得下的观测。记录有效期为一分钟，在到期前十秒内刷新。接收方为未来的到期时间留出五秒时钟偏差，已过期记录直接丢弃。端点、签名凭据或拓扑视图变化也会触发重新签名。接收方独立验签，缓存寿命受记录、证书和宿主授权中最早的截止时间约束。邻居通过通告确认收到记录的原始到期时间，后续通告可以省去已确认的记录。[签名介绍](../introduction.go) · [邻居通告](../discovery.go)

NAT 会合请求须到达目标本人。查询中的来源介绍由发布者签名，查询 ID 和目标由逐跳会话传递。目标节点依赖中间成员准确转述本次会合意图。双方交换签名介绍后，各自从静态配置和有效介绍中依次取出候选端点，按传输协议和物理地址去重。每轮打洞使用 QUIC 的 UDP 套接字，向每个获准且地址族可用的 UDP 端点各发一包。节点为每个 QUIC 邻居按地址族各保留一条有效的 UDP 源端点观测，新观测须通过物理端点校验和宿主的发布策略才会替换旧值。若 NAT 按目的地分配映射，能否直连仍取决于实际握手。[会合与打洞](../discovery.go) · [候选端点拨号](../dial.go)

配置标记为 `restricted` 的成员只与拓扑中列出的邻居直连。需要让子网节点只连网关时，在两端声明双向邻接，把网关设为 `transit`，并提供宿主认可的物理端点。本地 `SetPeerPathPolicy` 按对端公钥 `PeerID` 设置 `Auto`、`DirectOnly`、`RelayOnly` 或 `Blocked`。这些限制适用于拨号、打洞、会话准入及 QUIC 路径变化后的物理 UDP 收发。认证之前，UDP 过滤器只能识别物理端点。TCP 接入先检查源 IP，再用双向 TLS 区分共享地址的成员。TCP 确认及连接拆除由操作系统处理。[路径授权](../path_policy.go)

本机启用 `Options.Transport.HideEndpoints` 时，同一份签名介绍中的 `endpoints` 为空，邻居通告、查询来源、实时应答和缓存应答均遵守这一选择。QUIC 邻居仍可向本机报告它看到的源地址。本机跳过该观测，收到会合查询时仅回复签名介绍。主动连接和已建邻接仍能双向传输。电路检查的是逐跳身份与转发授权，允许没有公布端点的成员担任中继。[配置隐藏节点](integration.md#让节点通过已连接的邻居提供中继)

按成员建链时，任一方向注册的获准会话都能唤醒等待者。若一次建链成功但路径在等待结束前已被撤回，节点按当前策略再试一次。直连失败时也会重新读取策略，因此拨号期间从 `DirectOnly` 切到 `Auto` 可在同一轮尝试中继，切到 `Blocked` 则返回 `ErrPathPolicy`。[拨号实现](../dial.go) · [配置常驻邻居](integration.md#跨机器连接)

按成员身份直连时优先拨 UDP。两种传输都有候选时，TCP 等待 250 毫秒或 `DialTimeout` 的一半，取较短者。UDP 候选提前耗尽会立即启动 TCP。每种传输按顺序拨各自的端点，一条共享建链尝试最多并行一路 UDP 和一路 TCP。首条完成认证和注册的可用路径会结束这轮竞拨。QUIC 使用迁移后的当前地址，入站 TCP 的临时源端口只标识当前连接。每个成员在同方向、同传输和同地址族最多保留两条有效直连。

常驻邻居按 `MaintenanceInterval` 轮流使用 4 个后台建链名额。新路径注册后即安排首次邻居通告。探活成功后也交换通告。探活间隔较长时，节点按本路径上次发送的签名介绍的到期时间单独安排续期。

本机发起的探活与邻居通告共用四个并发名额，名额释放后继续处理排队的路径。常规探活按 `Probe.Interval` 调度，优先处理距上次探活最久的路径。实际间隔受路径数、应答延迟和超时影响。节点记录延迟、抖动和连续失败次数，QUIC 还提供路径 RTT 与丢包数据。成功应答将连续失败次数清零，达到 `Probe.FailureThreshold` 时关闭该路径。主题推送、补取和备用线路探测共用另外 8 个名额。[探活参数和默认值](integration.md#拨号探活与容量参数)

健康入站 TCP 会话的对端源 IP 与同地址族唯一的 TCP 候选 IP 相同时，后台探测跳过该反向拨号。其他地址族、多个 TCP 候选、UDP 候选和探活失败后的备拨仍按路径策略处理。显式调用 `ConnectEndpoint` 会验证目标的服务端身份。

健康路径按五个探活周期检查备用线路，最短间隔为五秒。首次探活失败后，距上次备拨满一个探活周期即可再试。遇到宿主出站策略拒绝的端点，会在同一轮继续检查其他候选。实际 UDP 试拨失败后，若会合成功，优先试拨新获知的可用 UDP 端点。若没有新端点且原端点仍获准，就在双方打洞后重试原端点。每轮最多重试一次。[路径探活](../probe.go) · [备用线路选择](../paths.go)

发送 IP 包时，若上次一般流量使用的路径仍获授权，且代价在最低值的 1.2 倍以内，就继续使用它。VIP 或下游地址需要另一张会话证书的授权时，只为该包选择合格路径。`Paths()` 和 `RecommendedMTU` 反映当前评分；查看状态、确认已有连接或后台探活都保留业务发送记录。[出队与发送](../ip_transmit.go)

一条电路最多包含 16 个节点，每跳检查整条路径、双向邻接、已认证的相邻成员及中间节点的 `Transit` 权限。中继先在一个 `DialTimeout` 内读完首帧，再按剩余路径长度给下游建链和上游就绪确认设置同一截止时间。中继转发两端的 TLS 字节流，可以看到电路路径、内层 ClientHello 和 ServerHello、传输时序与长度。集群授权和内层 IP 载荷受端到端 TLS 保护。

节点在等待下游确认前将新开的流登记到电路。撤回路径授权会关闭这些流，打断等待中的建链和已开始的转发。电路就绪后，中继释放建链请求的处理名额。每条物理 QUIC 连接的入站双向流额度覆盖本机电路上限和 64 条常规流。

节点先从目标反向计算最短跳数，再从短到长枚举无环路径。同跳数的首跳按源、目的和首跳公钥身份的稳定哈希值排列，先从各个首跳轮流试拨，再搜索其余候选。不同成员对可以使用不同首跳，同一成员对继续复用已建电路。一次建链在枚举阶段最多检查 4096 个邻接项、试拨八条电路。预算耗尽时，下次建链可在同一拓扑继续搜索。若接续搜索已到末尾且尚未找到候选，可用本轮剩余预算从头查找。[路径搜索](../relay_route.go) · [电路转发](../circuit.go)

## 数据交付、整形与主题消息

原始 IP 端口按完整成员身份排队。入队时检查当前拓扑，实际收发时按端到端会话的双端身份复核。主地址按唯一归属匹配，VIP 和下游路由分别取拓扑与会话证书精确地址、前缀授权的交集。集群 CA 的一对成员前缀定义同一逻辑链路。广播与组播按本机拓扑、地址作用域和订阅决定交付范围。站点 CA 的 IP 名称约束限制授权叶中的主地址，其 mesh 扩展还可收窄下游路由和 VIP 池。[广播与组播](addressing.md#广播与组播) · [出队和发送](../ip_transmit.go)

同一成员的主地址、VIP、下游地址和组投递共享一个有界队列。拓扑更新会清理失去授权的等待包，取消仍在等待建链或带宽的失权包。宿主也可调用 `IPPort.ClearPending(peerID)` 清理该成员的整个队列。[队列与地址授权](addressing.md)

每个中继在两个方向分别按已认证的入向邻居调度字节。同一邻居的全部电路合用一份，默认等权。`Options.RelayWeights` 可给指定邻居设置相对权重。多个邻居持续排队时，优先放行按权重折算后已获服务较少者。队列重新活跃时从当前调度进度参与，空闲份额可供其他邻居使用。

每条电路的每个转发方向使用一个 16 KiB 读缓冲。多个发送方同时排队或写入时，每次最多放行 4 KiB 中继数据。每个入向、出向邻居组合最多同时提交两个块，各电路独立写入。慢写占用该组合的写入名额，其他邻居组合仍可转发。相邻中继汇聚了多个成员时，只能在直接认证这些成员的那一跳分别调度。[部署示例](integration.md#中继额度权重与排空)

启用 `BytesPerSecond` 限速时，本机 IP 和主题消息作为同一个发送方，与各入向中继邻居共用节点级令牌桶，允许 64 KiB 突发。速率为零时，本机 IP 和主题消息直接放行。两种模式都按完整 IP 包、主题消息的 CMS 字节和中继数据块累计 `ControlStatus().BytesScheduled`。该计数在放行时增加，实际交付需看业务回执。相邻节点的探活和发现可另开流，经中继的端到端探活与业务共享加密电路，受排队和下游写入速度影响。

### 签名主题消息

成员的 `PublishTopics` 授予指定主题及其子树的发布权。节点验证发布者、签名、主题和有效期，按消息 ID 去重。首次接纳后，节点在后台名额可用时向其余直连邻居推送；错过推送的邻居可按通告中的清单补取签名原文。[主题消息实现](../publication.go) · [签名对象](pki.md#签名对象)

`Publish` 接受最多 4 KiB 载荷，将到期时间设为发布后五分钟。各节点的缓存截止时间取消息到期和签名者授权到期中的较早者，最多缓存 512 条。推送和补取应答在此期限内等待带宽，邻居会话关闭会取消等待，补取还受当前请求的截止时间限制。整形结束后重新检查缓存和会话授权。维护循环会清理过期记录，宿主更新授权后可用 `Revalidate` 复查。[订阅与交付结果](integration.md#主题消息与运行状态)

## 运行状态

`ControlStatus()` 报告本机资格、活动电路、拨号统计和监听错误。`Paths()` 给出各路径两端的证书序列号、授权期限和传输测量值。排查某个包时，可将 `ObserveTransmit` 记录的提交路径与应用回执关联。[状态 API](../status.go) · [运行状态与排障](integration.md#主题消息与运行状态)
